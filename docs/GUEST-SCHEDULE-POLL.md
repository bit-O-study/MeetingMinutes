# 일정 투표 (링크 참여형) — 기능 설계

작성일: 2026-11-24 · 상태: 설계안 (구현 전)

회원이 날짜 범위를 정해 투표를 만들고, **링크를 받은 사람은 로그인 없이 이름만 적고** 캘린더에서
**안 되는 날을 체크**한다. 결과는 날짜별 "가능 인원"으로 모아 최적 날짜를 고른다.

`CALENDAR-MEETINGS.md`의 모임 투표(스페이스 멤버 전용, 가능·조건부·불가)와 별개 기능이다.
그쪽의 "외부인 응답 링크"가 아직 안 된 항목이라, 이 기능이 그 자리를 채운다. 확정 뒤 이어 붙이는 방법은 §9.

---

## 1. 요구사항 → 결정

| 요구 | 결정 |
| --- | --- |
| 회원만 투표를 만든다 | 생성·수정·마감·삭제는 로그인 + 소유자만. 참여는 링크만 있으면 된다 |
| 몇 일부터 몇 일까지 | 시작일~종료일. 최대 60일(기존 모임 투표와 같은 한도) |
| 포함 안 되는 날을 수동 지정 | 생성 캘린더에서 날짜를 눌러 **제외일**로 칠한다. 제외일은 참여자 화면에서 회색·선택 불가 |
| 링크로 로그인 없이 참여 | `/v/[token]` 공개 경로. 토큰 해시로만 조회 |
| 이름·닉네임 필수 | 이름 입력 전에는 캘린더가 잠겨 있다. 비어 있으면 제출 불가 |
| 안 되는 날을 체크 | **기본은 전부 가능**, 안 되는 날만 눌러 "불가"로 바꾼다 (가능/조건부 3택 없음, 2택) |

"불가만 체크" 방식이라 응답이 가볍지만, **아무것도 안 눌렀다 = 응답 안 함인지, 다 된다는 뜻인지** 구분이 안 된다.
그래서 `제출` 버튼을 누른 사람만 참여자로 기록한다. 전부 가능해도 "제출"을 눌러야 한다(문구: "안 되는 날 없이 제출").

## 2. 화면

### 2.1 투표 만들기 `/polls/new` (회원)

```
제목        [ 12월 송년 스터디 ]
설명(선택)  [ 장소는 합정 예정 ]
기간        2026-12-01  ~  2026-12-31
┌───────── 12월 ─────────┐   월 단위 캘린더. 범위 밖 날은 흐리게
│ 일 월 화 수 목 금 토    │   범위 안 날짜를 누르면 → 제외일(사선 + 회색)
│  ·  1  2  3  4  5  6   │   제외일을 다시 누르면 해제
│ ...                    │   [주말 제외] [공휴일 제외 ✕v2] 프리셋 버튼
└────────────────────────┘
제외일 3개: 12/24(성탄 전야), 12/25, 12/31   ← 칩 목록, 사유는 선택 입력
마감        ( )없음 ( )내일 18:00 ( )3일 뒤 ( )1주 뒤 (•)직접 [2026-11-30] [18:00]
            → "11월 30일 (월) 18:00에 마감 · 6일 4시간 남음"  요약 한 줄
결과 공개   (•) 참여자 모두   ( ) 만든 사람만
                              [ 투표 만들기 ]
```

- 기간을 바꾸면 범위 밖이 된 제외일은 자동으로 버리고, 몇 개 버렸는지 알려 준다.
- 제외일이 기간 전체를 덮으면(후보 0일) 만들 수 없다.
- 마감 시각은 **서울 시간 기준**이다. 이미 지난 시각은 거절하고, 후보 첫날 이후로 잡으면
  "날짜가 지난 뒤에도 투표를 받게 돼요"라고 경고만 한다(막지는 않는다).
- 만들면 바로 공유 링크가 나오고 `[링크 복사]` 버튼을 보여 준다.

### 2.2 참여하기 `/v/[token]` (비회원 포함, 모바일 우선)

1. **이름 입력 단계.** 이름/닉네임 1~20자. 입력 전에는 아래 캘린더가 흐리게 잠기고 "이름을 먼저 적어 주세요" 안내.
2. 캘린더(기간이 걸친 달을 세로로 이어 붙임). 날짜 상태 3가지:
   - 가능(기본) — 흰 바탕
   - **불가** — 눌러서 토글, 붉은 바탕 + ✕ 아이콘 (색만으로 구분하지 않는다)
   - 제외일 — 회색 사선, 눌러도 반응 없음. 길게 누르면/호버하면 사유 표시
3. 데스크톱은 **드래그로 구간 칠하기**(첫 칸이 가능이면 불가로, 불가면 가능으로 일괄 전환). 모바일은 탭.
4. 하단 고정 바: `불가 3일 · [제출]`. 제출 뒤 "응답했어요" + 내 응답 수정 안내.
5. 수정: 같은 브라우저에서 다시 열면 이름과 체크가 그대로 복원된다(§4).
6. 결과 공개가 "참여자 모두"면 제출 후 §2.3의 요약을 보여 준다. 제출 전에는 **결과를 보여 주지 않는다**
   (남의 응답에 휩쓸리지 않게, 그리고 이름만 알면 훔쳐볼 수 없게).

### 2.3 결과 / 관리 `/polls/[id]` (소유자)

- 캘린더 히트맵: 날짜마다 "가능 n / 전체 m"을 색 농도 + 숫자로. 최다 가능일에 별표.
- 날짜를 누르면 그날 **못 오는 사람 이름 목록**.
- 우측 패널: 참여자 목록(이름, 제출 시각, 불가 일수, 🗑 삭제), 링크 복사, **마감 관리**, 투표 삭제.
- **마감 관리 카드:** 현재 마감 시각과 남은 시간, `마감 시각 바꾸기`(날짜+시간 입력),
  `+1일 연장` · `+3일 연장`, `마감 없애기`, `지금 마감` / `다시 열기`(마감 시각이 이미 지났으면 거절하고 시각을 먼저 바꾸게 한다 — 조용히 시각을 지우면 의도치 않게 마감 없는 투표가 된다).
  - 연장은 **현재 마감 시각에 더한다.** 이미 지났거나 마감이 없으면 "오늘 18:00"에 더한다.
  - 마감이 지난 투표를 연장하면 **자동으로 다시 열린다**(`closed` → `open`). 직접 마감한 경우도 같다.
  - `확정` 상태에서는 마감 관리가 잠기고, 먼저 `확정 취소`를 해야 한다. 다른 날짜로 다시 확정하는 것은 확정 취소 없이 된다. 확정을 취소할 때 마감 시각이 이미 지났다면 `closed`, 아니면 `open`으로 돌아간다.
  - 마감을 없애면 직접 마감하거나 날짜를 확정할 때까지 열려 있다.
  - 이미 제출된 응답은 연장·재개와 무관하게 그대로 남는다.
- `[이 날짜로 확정]` — 날짜를 고르면 투표가 `확정` 상태가 되고 참여 화면 상단에 확정 날짜를 띄운다.
  확정 후에도 되돌릴 수 있다(잠금 아님, 기존 원칙과 동일).
- 동률이면 상위 3개를 나란히 보여 주고 소유자가 고른다. 자동 확정은 하지 않는다.

### 2.4 목록 `/polls` (회원)

내가 만든 투표 목록: 제목 · 기간 · 참여 n명 · 상태(`진행 중`/`마감`/`확정 12/10`). 사이드바 또는 캘린더 화면에서 진입.

### 2.5 예외 화면

| 상황 | 참여자에게 보이는 것 |
| --- | --- |
| 없는 토큰 / 폐기 / 만료 / 삭제 | **모두 같은 "열 수 없는 링크" 화면.** 구분하지 않는다 (원칙 6과 같은 이유) |
| 마감·확정됨 | 제목, 확정 날짜(있으면)와 읽기 전용 캘린더. 수정 불가. "마감됐어요 · 고치려면 만든 분께 알려 주세요" 안내. 연장돼 다시 열리면 같은 링크로 바로 응답할 수 있다 |
| 인원 상한 초과 | "참여 인원이 가득 찼어요. 만든 분께 문의하세요" |

## 3. 데이터

새 테이블 4개. 전부 RLS 켬. 날짜는 `date`, 기준 시간대는 `Asia/Seoul`.

```
polls
  id uuid pk
  owner_id uuid → users (set null 아님: 소유자 탈퇴 시 cascade 삭제)
  title text (1~80) · description text (≤1000)
  range_start date · range_end date          CHECK end >= start AND end - start <= 59
  status text  open | closed | confirmed
  confirmed_day date null                    status='confirmed' 일 때만 값이 있다 (CHECK)
  result_visibility text  participants | owner
  respond_by timestamptz null                마감 시각. 지나면 서버가 거절 (소프트 아님: 이건 하드 마감)
                                             null = 마감 없음. 연장·변경·해제는 이 값과 status 만 바꾼다
  token text (암호문) · token_hash text unique    shares.ts 와 같은 방식(token-store)
  revoked_at timestamptz null
  max_participants int default 100
  version int default 1                      낙관적 잠금
  created_at · updated_at

poll_excluded_days
  poll_id → polls (cascade) · day date · reason text (≤40, 기본 '')
  PK (poll_id, day)                          CHECK 는 앱에서: day 가 범위 안일 것

poll_participants
  id uuid pk
  poll_id → polls (cascade)
  user_id uuid null → users (set null)       로그인 상태로 참여했으면 채운다
  display_name text (1~20)
  name_key text                              공백 제거·소문자 정규화. UNIQUE (poll_id, name_key)
  edit_token_hash text null                  비회원 본인 수정용 (§4). 회원은 null
  submitted_at · updated_at
  UNIQUE (poll_id, user_id) WHERE user_id IS NOT NULL

poll_unavailable_days
  participant_id → poll_participants (cascade) · day date
  PK (participant_id, day)                   "불가"인 날만 저장 = 행이 곧 체크
```

- **불가인 날만 저장**한다. 가능일 수는 `후보일 수 - 제외일 - 불가일`로 계산한다.
- 제외일이 나중에 늘어도 기존 `poll_unavailable_days`는 그대로 둔다. 집계할 때 제외일과 겹치는 행은 무시한다.
- 참여 `답변 수정`은 `poll_unavailable_days`를 통째로 교체(삭제 후 삽입)하되 한 트랜잭션으로 묶는다.
- 마이그레이션은 `npm run db:generate` 후 `docs/work-split.md` 변경 로그에 한 줄. **운영 적용은 `apply-calendar-meetings.mjs`처럼 직전 번호를 확인하는 전용 스크립트로**
  (CALENDAR-MEETINGS.md의 drizzle-kit migrate 주의 참고).

## 4. 비회원 신원 — 로그인 없이 "내 응답"을 어떻게 알아보나

| 상황 | 방식 |
| --- | --- |
| 비회원 첫 제출 | 서버가 무작위 `edit_token`을 만들어 **HttpOnly 쿠키**(`poll_<pollId>`, 90일)로 내려 주고 해시만 저장 |
| 같은 브라우저 재방문 | 쿠키가 있으면 참여자를 찾아 체크를 복원, 수정 가능 |
| 다른 기기·쿠키 삭제 | 본인 응답을 되찾을 수 없다. **같은 이름으로 새로 제출하면 이름 충돌**(아래) |
| 로그인한 회원이 링크를 열면 | 이름 입력을 건너뛰고 계정 이름으로 참여. 회원은 `user_id`로 응답이 하나로 합쳐져 기기가 바뀌어도 복원된다. 이름 옆 `회원` 표시 |

**이름 충돌:** 이름은 `name_key`로 정규화해 투표 안에서 유일하다.
- 같은 이름이 이미 있고 내 쿠키가 아니면 → "이미 쓰는 이름이에요. 다른 이름을 적거나, 본인이라면 처음 쓰던 기기에서 수정해 주세요"
- 남이 내 이름으로 덮어쓰는 것을 막기 위함이다. 대신 기기를 바꾸면 이름을 살짝 바꿔야 한다(예: `민수2`). 소유자가 중복 행을 삭제할 수 있다.
- 회원 이름과 같은 이름을 비회원이 쓰는 건 막지 않는다(사칭 방지는 `회원` 배지로 구분).

## 5. 서버 동작

권한 검사는 기존 규칙을 따르되, 이 기능은 스페이스 경계 밖이라 **별도 모듈 `src/lib/poll-access.ts`**를 둔다.

| 동작 | 호출자 | 검사 |
| --- | --- | --- |
| `createPoll` · `updatePoll` · `closePoll` · `reopenPoll` · `deletePoll` · `rotateLink` | 회원 | 세션 필수 + `owner_id = 나`. 남의 투표는 "없는 투표"와 같은 응답 |
| `setDeadline(pollId, respondBy | null, version)` | 소유자 | 마감 변경·연장·해제 공용. 아래 규칙 참고 |
| `confirmPollDay` · `unconfirmPoll` | 소유자 | `UPDATE … WHERE status <> 'confirmed'` 한 번으로 동시 클릭 방지, 버전 비교 |
| `removeParticipant` | 소유자 | 투표 소유 확인 후 삭제 |
| `getPollForVoting(token)` | 누구나 | 토큰 해시 조회 → 폐기·만료·삭제는 전부 `null` |
| `submitVote(token, name, days[])` | 누구나 | 아래 검증 |

`setDeadline` 규칙:
- 새 값은 **지금보다 뒤**여야 한다(해제 `null`은 허용). 과거 값은 거절.
- `status = confirmed`면 거절(먼저 확정 취소). 그 외에는 `status`가 `closed`여도 새 마감이 미래면 **`open`으로 되돌린다.**
- `version`이 다르면 거절하고 최신 값을 다시 보여 준다(두 사람이 동시에 연장해도 마지막 것이 조용히 덮지 않게).
- 연장 버튼은 클라이언트가 새 시각을 계산해 이 액션 하나로 보낸다. 서버가 "+N일"을 따로 알 필요는 없다.
- 변경 이력은 남기지 않는다(감사 로그 비범위). 참여자에게 알림도 없다 — 이미 응답한 사람이 마감 연장을 알 방법은 링크를 다시 열어 보는 것뿐이다.

`submitVote` 검증 (전부 서버에서. 클라이언트 검사는 편의일 뿐):
1. 토큰 유효 · `status = open` · 마감 시각 이전
2. 이름 1~20자, 제어문자 제거, 앞뒤 공백 정리 (HTML 이스케이프는 React가 처리)
3. `days`는 `YYYY-MM-DD` 형식, **중복 제거, 범위 안, 제외일 아님**, 최대 후보일 수. 어긴 값은 조용히 버리지 않고 거절
4. 인원 상한 `max_participants`
5. 신원: 로그인 → `user_id` upsert / 쿠키 있음 → 그 참여자 수정 / 둘 다 없음 → 새 참여자(+쿠키 발급)
6. **속도 제한**: IP + 토큰 기준 분당 10회. 기존 `auth-attempt-buckets`를 일반화해 재사용
7. 저장은 참여자 upsert + 불가일 교체를 한 트랜잭션으로

공개 경로 `/v/[token]`은 로그인 리다이렉트 대상에서 빼야 한다(`/p/[token]`과 같은 처리를 확인해서 맞춘다).
이 경로는 **캐시하지 않는다**(`no-store`) — 참여 인원·확정 상태가 바로 반영돼야 한다.

### 노출 범위 — 링크 하나로 알 수 있는 것
- 투표 제목·설명·기간·제외일(사유 포함)·확정 날짜, 그리고 공개 설정이 `participants`이고 **제출한 뒤라면** 날짜별 가능 인원 숫자와 상위 3일. 다른 참여자의 **이름은 참여자에게 내보내지 않는다**(이름은 만든 사람 화면에서만 본다).
- **노출하지 않는 것:** 소유자의 이메일·계정 정보, 연결된 스페이스·노트 이름, 다른 투표 목록.
- `검색엔진 노출 방지`: `<meta name="robots" content="noindex">` + `X-Robots-Tag`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`(`next.config.ts`의 `/v/:token*`).

## 6. 상태

```
open ──(마감 버튼 / 마감 시각)──▶ closed ──(다시 열기 / 마감 연장)──▶ open
open | closed ──(날짜 확정)──▶ confirmed ──(확정 취소)──▶ open
```

- `closed`·`confirmed`에서도 소유자는 결과를 계속 볼 수 있다. 참여자는 읽기 전용.
- 마감 시각이 지나도 DB의 `status`는 `open`으로 남는다(스케줄러 없음). 표시와 쓰기 거절은 조회 시점에 계산하므로
  **연장은 `respond_by`만 바꿔도 즉시 효과가 난다.**
- "지연"에 해당하는 개념은 없다. 마감 시각 경과는 저장하지 않고 조회 시 계산한다(`isClosed = status≠open || respond_by < now`).

## 9. 열린 질문

1. **스페이스와 연결하나?** 기본안은 **스페이스와 무관한 개인 소유 투표**(`/polls`). 스페이스 `일정` 탭에서 "외부 참여 투표" 버튼으로
   만들고 확정 시 기존 `meetings`(confirmed)로 승격하는 방식은 3차에 둔다. 처음부터 필요하면 `polls.space_id null` 한 칸만 추가하면 된다.
2. **비회원 가능/불가 2택으로 충분한가?** "되면 좋음(조건부)"이 필요하면 `poll_unavailable_days`에 `answer`를 넣어 3택으로 넓힐 수 있다. 지금은 요청대로 불가만.
3. **결과 공개 기본값.** 참여자 모두(조율에 유리) vs 소유자만(눈치 방지). 기본안은 참여자 모두, 제출 후에만 보인다.
4. **익명 허용?** 이름을 필수로 했으므로 익명 투표는 하지 않는다.
