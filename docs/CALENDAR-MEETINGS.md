# 통합 캘린더 · 모임 일정 투표

개인 일정·할 일, 스페이스 할 일, 확정·투표 중 모임을 한 캘린더에서 보고, 모임 날짜를 캘린더에서 칠해 정한다.

## 배포 순서 — 반드시 이 순서

1. **마이그레이션 `0011`을 운영 DB에 먼저 적용한다.**
   ```bash
   node scripts/apply-calendar-meetings.mjs --check   # 상태만 확인(아무것도 바꾸지 않음)
   node scripts/apply-calendar-meetings.mjs           # 적용
   ```
2. 그다음 앱을 배포한다. 순서가 바뀌면 새 화면이 없는 테이블을 읽다 실패한다.

`drizzle-kit migrate`는 쓰지 않는다. 0008·0009·0010이 별도 스크립트로 적용돼 저장소 journal 과 DB 기록이 어긋나 있어서,
migrate 가 이미 적용된 마이그레이션을 다시 실행한다. 위 스크립트는 직전 마이그레이션이 정확히 0010 일 때만 적용하고,
한 트랜잭션이라 중간에 멈춰도 반쯤 적용되지 않는다. 적용 뒤 RLS·제약·컬럼을 검증하고 하나라도 틀리면 전체를 되돌린다.

## 무엇이 바뀌었나

| 영역 | 내용 |
| --- | --- |
| DB | `meetings`, `meeting_responses`(RLS 켜짐). `personal_planner_items`에 여러 날 일정 허용, 할 일 연결 컬럼 `linked_item_id`·`linked_meeting_id` |
| 캘린더 | `/calendar` — 월(막대·칩), 주(시간표), 모바일(점+목록), 레이어(개인·스페이스) 켜고 끄기 |
| 모임 | 스페이스 `일정` 탭, `/s/[spaceId]/m/[meetingId]` 투표 화면, 확정 시 채팅 공지·회의록 노트 |
| 할 일 | 연결된 일정·모임 칩, 편집 창의 "딸린 일정" 선택 |

기존 일정·할 일은 그대로 유효하다(하루짜리 일정은 `fixed`로 남는다).

## 설계 결정

- 스페이스 할 일과 확정된 모임은 **복사하지 않고 조회할 때 합친다**. 원본이 바뀌면 캘린더도 바뀐다.
- 스페이스 할 일은 **나에게 배정됐거나 담당이 없는 것**만 올린다(남의 것까지 섞으면 정작 내 일정이 안 보인다).
- 모임 후보는 시각이 아니라 **날짜**다. `span_days`가 2 이상이면 이어지는 날짜 구간(1박2일 등)을 찾는다. 시각은 확정할 때 정한다.
- 내 개인 일정과 겹치는 날은 **나에게만** 보인다. 다른 멤버에게 전달하지 않는다.
- 확정은 `UPDATE … WHERE status = 'polling'` 한 번으로 막아 동시에 눌러도 한 번만 성공한다.
- 지연은 상태가 아니라 계산 결과다(기존 원칙 유지).

## 검증

단위 테스트: `npm run test` (배치·추천 점수·변환 규칙)

화면 점검은 DB·로그인 없이 개발 서버의 고정 데이터 미리보기(`/dev/*`, 운영에서는 404)로 한다.

```bash
npm run dev -- -p 3210            # DATABASE_URL 은 아무 값이나 있으면 된다
node scripts/audit-layout.mjs http://localhost:3210                     # 폭 360~1440 에서 겹침·넘침·잘림·가로 스크롤 측정
node scripts/verify-calendar-ui.mjs http://localhost:3210               # 캘린더 상호작용
node scripts/verify-meeting-ui.mjs http://localhost:3210                # 모임 투표·만들기·확정
```

Playwright 가 이 저장소의 의존성이 아니므로 `PW_MODULE`(패키지 경로)과 `CHROME_PATH`(브라우저 실행 파일)를 환경변수로 줄 수 있다.
`audit-layout.mjs`는 다른 경로도 인자로 받는다(`/dev/calendar?view=week&day=2026-11-12`, `/dev/meeting`, `/dev/meetings?open=1` 등).

## 아직 하지 않은 것

- 모임 확정 시 멤버별 알림(앱에 알림 기능이 없다). 지금은 채팅 공지와 목록의 "내 응답 필요" 배지로 알린다.
- 외부인(비멤버) 응답 링크.
- 일정 끌어서 옮기기, 사용자별 시간대, "보기 크기: 크게" 설정.
- 여러 날에 걸친 일정의 시각 지정(2박3일 MT 18:00 출발 등). 여러 날 일정은 종일로만 둔다.
